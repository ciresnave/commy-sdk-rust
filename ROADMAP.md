## Breaking release 0.15.0: tenant sessions (audit-2 typestate) and named-variable removal (audit-3)

Decided with the PM 2026-10-23: one breaking minor (pre-1.0, so 0.14 to 0.15) so users migrate once. Built: audit-3 in 0.15.0, the `Session` typestate in 0.15.1 (the steps below are the record of the design).

### audit-3 becomes a deletion

commy removed the named-variable messages (Plan C6). At commy origin/main 000ab7e the server answers `AllocateVariable`, `ReadVariable`, `WriteVariable`, `DeallocateVariable`, `Subscribe` and `Unsubscribe` with an "unknown message type" `Error` (test `the_named_variable_messages_are_gone`), and `commy-wire` 0.5 has no `Subscribe` or `VariableChanged`. So adding `request_id` to them is moot, and meanwhile the SDK's `write_variable`/`subscribe`/`unsubscribe` never read that error reply, which is exactly audit-3's stale-reply bug against a current server. Plan: delete `read_variable`, `write_variable`, `subscribe`, `unsubscribe` and the `ReadVariable`/`WriteVariable`/`Subscribe`/`Unsubscribe`/`AllocateVariable`/`DeallocateVariable` client messages and `VariableData`/`VariableChanged` server messages, with their tests and docs (`CRUD_API_REFERENCE.md`, `MIGRATION_GUIDE.md`). The shared-file calls (`open_shared`, `shared_write`, ...) are the replacement. Waiting on the commy lane to confirm C6 is permanent.

### audit-2 typestate: `Session`, a tenant-bound handle returned by `authenticate`

Today every operation is a method on `Client` and checks authentication at runtime (0.14.1 made that uniform). Goal: calling a session operation without having authenticated does not compile.

Shape (recommended, option B):

- `Client` keeps what needs no session: `new`/`with_id`/`with_*`, `connect`, `disconnect`, `heartbeat`, `is_connected`, `connection_state`, `id`, `server_url`, `idle_seconds`.
- `Client::authenticate(&self, tenant_id, credentials) -> Result<Session>` returns the new type. `Session` is `Clone`, owns a cheap clone of the client (its fields are already `Arc`s) and the tenant id it was authenticated for.
- Everything that needs a session moves to `Session`, with the tenant implicit: `create_service(name, size)`, `get_service(name)`, `delete_service(name)`, `create_tenant`, `delete_tenant`, `grant`/`revoke`/`list_grants`/`set_local_mapping`, `negotiate_local`, `open_shared`/`open_remote`/`shared_read`/`shared_write`/`flush_shared`/`poll_shared_*`, `request_rotation`/`drain_for_rotation`/`begin_fill`/`finish_fill`/`abort_fill`/`complete_rotation`, and the virtual-file and watcher calls.
- `authenticated_tenants`/`is_authenticated_to` stay on `Client` (they read state); `Client::initialize` returns `(Client, Session)`.

Why a tenant-bound handle and not `Client<Authenticated>`: authentication here is per tenant and additive (a connection can authenticate to several tenants, and a tenant can be lost), so one state parameter on `Client` would still need the runtime tenant check it was meant to remove. A `Session` encodes the fact that matters (authenticated *to this tenant*), removes the repeated `tenant_id` argument, and a second `authenticate` gives a second `Session` on the same connection.

What the type system does not give: a `Session` can outlive its authentication (disconnect, server-side loss, revoke). Those calls still return `ConnectionLost`/`PermissionDenied` at runtime; the types only rule out "never authenticated". The server stays the enforcer (it answers `UNAUTHENTICATED` to everything but `Authenticate`, `Heartbeat`, `Disconnect`).

Alternative considered (option A): `Client<Unauthenticated>` / `Client<Authenticated>` consuming `authenticate(self)`. Smaller diff to the call sites, but multi-tenant stays runtime-checked, `Client` becomes generic everywhere it is stored, and a failed `authenticate(self)` has to hand the client back inside the error. Not recommended.

Migration: `client.create_service(t, n, s)` becomes `let s = client.authenticate(t, creds).await?; s.create_service(n, s)`. No compatibility shims (pre-1.0, one migration); `MIGRATION_GUIDE.md` gets a before/after for each moved call, examples and `tests/e2e.rs` move over, and `inject_auth_for_test` becomes a `Session` constructor for tests.

Steps, each red-first: (1) delete the named-variable calls (smallest, independent); (2) add `Session` and move the operations; (3) docs and examples; one version bump to 0.15.0 at the end, proposed to the PM. Open for the PM/CireSnave: the name `Session` (vs `TenantClient`), and whether `create_tenant`/`delete_tenant` belong on `Session` (the server requires an authenticated session, so yes here).
