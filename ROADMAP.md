# Roadmap (SDK lane)

Authoritative portfolio priorities live in the portfolio roadmap; this file records what is specific to this repository.

| # | item | state | note |
|---|---|---|---|
| 5.1g | The 5 `#[ignore]` integration tests (`tests/integration_examples.rs`) | done | Replaced by real assertions in `tests/e2e.rs` (connect and authenticate, service lifecycle and heartbeat, several clients) running in the required CI job `e2e (real commy server)` against a pinned commy build with a real self-signed certificate; the placeholder-certificate `CommyServer::prepare` path is no longer used by any test and no `#[ignore]` remains in the repo. |
| audit-2 | Operations run unauthenticated: only `create/get/delete_service` check authentication; `create_tenant`, `delete_tenant`, `read/write_variable`, `subscribe`, `unsubscribe`, `heartbeat` do not (and the server does not check either) | open | Needs server enforcement plus an `Authenticated<Client>` typestate (breaking). |
| audit-3 | Replies are matched to requests only by arrival order; `write_variable`/`subscribe`/`unsubscribe` never read their reply, so the next call consumes a stale one | partly done (0.11.0) | Needs `request_id` on every request echoed in the reply (wire contract with Commy). | 0.11.0: `ServerMessage::Error` carries the optional `request_id` the server echoes, and every call that waits on a `request_id` (negotiate, flush, resync, rotation, grants) ignores an error naming another request. The legacy CRUD messages (`write_variable`, `subscribe`, `unsubscribe`) still have no `request_id` on the wire.
| audit-4 | Wire disagreements with the server: `api_key` vs `key`, error-code spelling | done (0.12.0) | Shared wire-types crate (`commy-wire`) with golden vectors. | 0.11.0: `ErrorCode` accepts every commy-wire code (`UNAUTHENTICATED`, `RATE_LIMITED`, `UNSUPPORTED_VERSION`) and any unknown code, which used to make the whole error message fail to parse and the caller time out instead of seeing the error. `api_key` vs `key` is for the legacy Authenticate. 0.11.2: `ErrorCode` also reads the CamelCase spellings (`NotFound`, `Unauthorized`, `InvalidRequest`, `InternalError`) that commy's legacy handlers still send; the server should move them to the wire spelling. 0.12.0 (commy-wire 0.4.0, R1 gate item 1): `ClientMessage::Authenticate` and `ServerMessage::AuthenticationResult` are now the wire types (request id, protocol version, `method` + credential fields, optional `client_id` / `dev_scopes` / `client_version`); `api_key` vs `key` is settled by the wire spec. The result's `request_id` is matched. 0.13.0 drops the tolerance for servers older than commy 0.15.0 (commy-wire 0.4.0): an `AuthenticationResult` without a `request_id` is refused, so `authenticate` times out against them; the e2e job runs against commy 0.16.0 (dev authentication, `COMMY_ALLOW_DEV_AUTH=1`). |
| S1-S8 | Local zero-copy shared-memory byte sharing per the approved Commy plan | done | S8 done (0.2.4: deps refreshed, repo URL fixed, "complete"/"production-ready" claims removed, stray logs and `Cargo.toml.orig` dropped). S1 file-open + nonce read + fallback and the S2 SDK-only alias are in `src/local_map.rs` (0.2.3). The handshake (`Client::negotiate_local`, commy-wire 0.2.1) is in 0.3.0. `SharedFile` (scan-mode write_range/commit/apply_inbound on dirty-ranges 0.0.5) is in 0.3.1 (S6/S7 scan side). `Client::open_shared`/`shared_write`/`flush_shared`/`poll_shared_updates` (local mode, scan) are in 0.4.0 with commy-wire 0.2.4 forwarding. Remote mode (`Client::open_remote`, binary range frames, Resync, FlushEnd) is in 0.5.0. Rotation (S5: `drain_for_rotation`, `complete_rotation`, `request_rotation`, `poll_shared_events`) is in 0.6.0. The write trap and mode switch (S3/S4: `SharedFile::arm_trap`, `set_page_mode`, dirty-ranges 0.1.1) are in 0.6.1, opt-in; in 0.6.2 a local-mode foreign `RangesUpdated` on a trapped page is re-baselined with dirty-ranges 0.1.2 `Region::rebaseline` (no write-back), and `Client::arm_shared_trap` opts a mapped service in. Breaking in 0.7.0: `create_service(tenant, name, size)` now sends the `size` the server has required since commy 0.5.0 (the SDK never sent it, so every `create_service` failed against a current server); new `Client::with_tls_root_pem` (trust a self-signed server) and `Client::shared_read`. End-to-end tests (`tests/e2e.rs`, feature `e2e`, `COMMY_BIN`) run in the CI job `e2e` against commy 0.7.1 built from a pinned SHA: TLS with a pinned self-signed root and remote-mode exchange between two clients. Breaking in 0.8.0 (commy-wire 0.3.0, prepare/commit resize): `drain_for_rotation` returns `RotationOutcome` (`Committed`, `Aborted`, or, for the requester, `Prepared`); the requester fills the new file with `begin_fill` / `RotationFill::write` / `finish_fill` (or `abort_fill`), local through the prepared `path` and remote as range frames for the new file id; an abort reopens writes on the old file and the first of commit/abort ends a rotation. Covered end to end (0.8.1, remote mode, commy 0.9.0 at a pinned SHA): a resize where the requester migrates the layout and both clients switch, and an abort where writers resume on the old file. Grants (0.9.0, commy-wire 0.3.1, commy 0.10.1): `Client::grant`, `revoke` and `list_grants` (replies matched on `request_id`, requests validated before sending); services now need a grant on the server (the creator gets `service:admin`). The dev-auth binary makes every client tenant admin and files grants under a server session id no client can learn, commy 0.11.2 fixes that, and 0.10.0 makes the SDK send its `client_id` in `Authenticate` (breaking: new fields on `ClientMessage::Authenticate`, `client_id` on `AuthenticationResult`) plus `Client::with_dev_scopes` (development servers: `&[]` = holds no grant). Covered end to end: a client without a grant is denied, allowed after `grant`, and dropped with `Loss{REVOKED}` and denied again after `revoke`. `Client::set_local_mapping(service, enabled)` (0.10.1, commy-wire 0.3.2; needs `service:admin`; local mapping is closed by default) opens a service to local mapping. A straggler is covered end to end (R1 gate item 3): with `COMMY_DRAIN_TIMEOUT_MS=500` a member that sees the barrier open and never drains is told `Loss{ROTATION_STRAGGLER}`, loses its mapping, and the resize still commits for everyone who drained. Durable state is covered end to end (0.11.1, commy 0.13.0): a service id, its registry entry and a client's grant survive a server kill and restart on the same state directory, and so does a revoke (a restart does not give the access back). Local mode is covered end to end (0.10.2, commy 0.12.0): the service is opened with `set_local_mapping`, two local clients and a remote one share the file, the write trap reports trapped writes without echo, and a resize is filled through the prepared file. 0.10.2 also fixes `open_remote`, which confirmed a local mapping it was offered and so was treated by the server as a local mapper whose range frames are refused. Conformance (0.11.3, commy R1 gate item 2): `tests/wire_vectors.rs` runs the golden vectors of the pinned `commy-wire` (found with `cargo metadata`) through the SDK's own `ClientMessage`/`ServerMessage`: every valid control message the SDK carries round-trips equal, every invalid one is refused except the documented tolerance (legacy error spelling), and the one wire message the SDK does not carry as such is listed with its reason: `Authenticate` (the SDK sends its own shape and the server answers with an `AuthenticationResult` that has no wire counterpart; for the R1 freeze decision). Platform status (0.11.5, commy R1 gate item 5): `PLATFORMS.md` names every OS and architecture as TESTED or UNVERIFIED for the library tests, the e2e job against the real server, and write detection (scan is the default everywhere; the trap is opt-in and never the default). CI hygiene (0.13.1, CodeRipper WSP-001/SUP-001): `.github/CODEOWNERS` and `--locked` on every cargo call in CI. Generation removed (0.14.0, commy-wire 0.5.0; CireSnave 2026-10-21: the SDK does not track how many times a service has been rotated): `SharedFile::generation`/`set_generation` are gone and `complete_rotation` treats a commit whose `new_file_id` is the already-mapped file as a duplicate (`RotationCommit` keeps `rotation_id`, loses `generation`); the e2e job runs against commy 0.19.0. |
